# 双摄像头控制台

同一套固件通过编译配置分为推流机、检测机；网页控制台统一代理设备接口并保存检测机发送的 JPEG。两台摄像头通过局域网工作，不需要互接 GPIO 或串口。

## 分工

| 设备 | CAMERA_ROLE | 行为 |
| --- | --- | --- |
| A：推流机 | `1` | 持续采集、JPEG 编码、提供预览；不运行移动检测 |
| B：检测机 | `2` | 默认 VGA 原始像素检测；无事件时跳过 JPEG 编码；触发时抓拍并推送 |
| 兼容单机 | `0` | 持续预览与移动检测同时运行；未配置角色时采用此模式 |

检测机仍可通过 `/snap`、`:81/stream` 调试预览；收到请求会开启短期编码，停止请求 2 秒后恢复仅检测。控制台选择检测机时只显示状态与事件，不会自动拉取检测机预览；检测机同样可以在控制台切换检测分辨率，切换会短暂停止采集并重建基准。查询 `/set`、`/motion` 不会开启编码。

检测机默认 VGA（640×480），触发照片为 640×480；控制台也可改为 SVGA（800×600）。采样算法只读取归一化的 32×24 个亮度点，所以提高分辨率不会按像素数同比增加算法工作量，但高分辨率会让摄像头帧缓存占用和传感器采集负载上升。JPEG 只在事件或预览请求时编码，因此高分辨率抓拍主要增加事件发生时的单次编码时间，不会让检测机持续压缩视频。VGA 是较稳妥的默认值；SVGA 需实机确认检测响应和可用 PSRAM。

检测机空闲时不进行 JPEG 编码，能降低 CPU 负担。帧差算法仍按 200 ms 间隔采样；触发事件的照片来自检测机自身。两台设备的视野和时间不会自动同步，也不从推流机补拍。若需要用检测机触发推流机抓拍，需要另行增加跨设备触发协议。

## 固件配置

将 `firmware/esp32_cam_final/config.example.h` 复制为同目录的 `config.local.h`，两台设备分别构建。

推流机配置：

```cpp
#pragma once
#define CAMERA_ROLE 1
#define CAMERA_WIFI_SSID "你的 WiFi"
#define CAMERA_WIFI_PASSWORD "WiFi 密码"
#define CAMERA_AUTH_USER "cam"
#define CAMERA_AUTH_PASSWORD "摄像头访问密码"
```

检测机配置：

```cpp
#pragma once
#define CAMERA_ROLE 2
#define CAMERA_WIFI_SSID "你的 WiFi"
#define CAMERA_WIFI_PASSWORD "WiFi 密码"
#define CAMERA_AUTH_USER "cam"
#define CAMERA_AUTH_PASSWORD "摄像头访问密码"
#define MOTION_ENABLED true
#define MOTION_WEBHOOK_URL "http://192.168.1.10:8080/api/events"
#define MOTION_WEBHOOK_TOKEN "与控制台配置一致的随机令牌"
```

示例 IP `192.168.1.10` 应替换为运行控制台的电脑或服务器的局域网 IP。账号密码可以各不相同，由控制台分别配置。默认固件配置仍可兼容之前直接编辑主文件的用法，推荐将连接信息移到被 Git 忽略的本地配置中。

## 启动双机控制台

运行环境为 Python 3.10 或更高版本，不需要安装第三方包。

```powershell
Copy-Item console/config.example.json console/config.local.json
```

填写本地配置：

```json
{
  "username": "admin",
  "password": "替换为至少8位的控制台密码",
  "webhook_token": "与检测机配置一致的随机令牌",
  "retain_events": 20,
  "preview_fps": 5,
  "status_poll_seconds": 10,
  "stream": {
    "name": "客厅 · 实时画面",
    "url": "http://192.168.1.101",
    "username": "cam",
    "password": "推流机访问密码"
  },
  "detector": {
    "name": "入口 · 移动检测",
    "url": "http://192.168.1.102",
    "username": "cam",
    "password": "检测机访问密码"
  }
}
```

```powershell
python console/server.py --host 0.0.0.0 --port 8080
```

浏览器访问 `http://<服务器局域网IP>:8080`。默认不带参数时仅监听 `127.0.0.1:8080`，便于本地开发；监听局域网时要求先配置至少 8 位的控制台密码。设备、令牌和访问密码不会通过状态接口发给浏览器。本地配置文件和抓拍数据目录已加入 Git 忽略。

网页包含：

- 摄像头列表与在线状态，运行角色不一致时给出提示。
- 实时预览、暂停/继续、保存当前照片、全屏、推流机与检测机分辨率切换。
- 实际画面接收帧率、处理耗时、JPEG 质量、设备角色。
- 检测状态、最近抓拍、变化比例、推送成功与失败次数。
- 最近 5 条事件快捷入口；服务器默认保存最近 20 张，可设置 `retain_events`（1–500）。

照片和事件元数据保存在 `console/data/`，控制台重启后恢复历史。时间显示为浏览器本地时间，事件时间是服务器接收时间。控制台尚未收到推送但检测机已有照片时，会尝试显示检测机最近抓拍；设备重启后该内存照片清空，控制台已保存的历史仍保留。

这是局域网服务；外网部署时在前方配置 HTTPS 反向代理。HTTP Basic Auth 与 Bearer token 在明文 HTTP 链路上传输，公网不可直接裸露。控制台接收并保存照片，不额外向微信等平台转发。

## 板载网页与开发

两台设备直接访问自身 `/` 也可使用新版界面，但只管理当前设备。单块板上的网页不会自动发现另一台设备；双机统一管理使用上面的 Python 服务。

UI 唯一源文件为 `web/index.html`。修改后执行：

```powershell
python tools/embed_web.py
python tools/embed_web.py --check
```

生成的 `firmware/esp32_cam_final/web_ui.h` 随固件进入 Flash，无外部字体或脚本依赖；运行时不需要文件系统。

## 玩客云 / 小内存 NAS

推荐直接使用系统 Python 运行单个进程，不需要 Docker、Node.js、数据库、OpenCV、FFmpeg 或服务端浏览器。网页由手机/电脑渲染；图像检测和 JPEG 编码均在 ESP32 上完成。NAS 只做带认证的 HTTP 中转、状态查询和抓拍落盘。

默认资源限制：

- 最多 4 个 HTTP 请求线程，连接队列长度 4；连接读写超时 5 秒。超出请求数直接关闭连接，客户端稍后重试，不创建更多线程。
- 最多 1 个设备中转请求和 1 个事件接收请求同时处理；通道繁忙返回 429。总请求满载时抓拍也可能被拒绝，当前没有可靠送达保证。
- JPEG 最大 256 KiB，不解码、不转码、不做 Base64。没有常驻多帧队列或照片缓存；请求结束后释放照片引用。Python 分配器是否立即归还内存由运行时决定。
- 默认单页预览上限 5 fps，`preview_fps` 可在 1–15 间调整；更省资源可设为 2 或 3。暂停画面或网页隐藏时停止取帧。此上限在前端执行，不是服务端全局流量配额；多个观看者会增加流量，建议单个观看者使用。
- 状态查询使用一个后台线程，默认间隔 10 秒，按顺序查询两台设备；没有浏览器读取状态约 30 秒后停止设备轮询（已开始的查询会完成），抓拍接收持续工作。网页仍每 3 秒读取缓存的状态，设备状态可能延迟一个轮询周期。
- 默认只保留最近 20 张抓拍，照片在磁盘，内存只保留有上限的事件元数据；`/api/state` 只返回最近 5 条。20 张照片按最大尺寸约占 5 MiB 磁盘，另加少量 JSON。请将 `--data-dir` 指向外置磁盘，避免长期写入系统闪存。

启动示例（路径按 NAS 挂载位置修改）：

```sh
python3 console/server.py --host 0.0.0.0 --port 8080 --data-dir /mnt/usb/camera-events
```

需要 Python 3.10+。本机测试不代表玩客云 ARM 系统的实测 RAM：部署后可用 `ps -o pid,rss,vsz,cmd -p <PID>` 查看 RSS（KiB），分别观察空闲、打开预览、连续抓拍三种状态。不要将磁盘存储上限或 JPEG 大小当作 Python 进程总内存。
